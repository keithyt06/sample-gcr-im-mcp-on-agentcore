# 企业微信配置（`im: wecom`）

企业微信与另外三个 IM 不同：**不需要在开发者后台创建应用，也没有应用密钥。**每个用户用企业微信手机端扫码授权，从而创建（或绑定）一个属于自己的**智能机器人**，官方 `wecom-cli` 用它执行调用。每个用户的凭证由服务加密保存。

配置：设置 `im: wecom`。没有企业微信凭证配置项，也不用执行 `npm run secret:set-im-app`。可选的 `wecom:` 块有两个配置项：

```yaml
im: wecom
wecom:
  requireApproval: true   # 建议开启；默认 false
  maxPendingQr: 20        # 默认 20
```

| 配置项 | 默认值 | 含义 |
|---|---|---|
| `wecom.requireApproval` | `false` | 新的企业微信用户处于 `pending_approval` 状态，在运维人员执行 `npm run users -- approve <userId>` 之前拿不到 MCP token。**建议设为 `true`。**见[没有租户边界](#没有租户边界请开启审批) |
| `wecom.maxPendingQr` | `20` | 整个部署同时进行中的扫码登录上限（每个登录最长占用一个 AgentCore 会话 300 秒）。每个来源 IP 最多同时 3 个。超过上限时，授权页返回 HTTP 429"当前进行中的登录过多" |

## 没有租户边界：请开启审批

飞书、Lark、钉钉应用只允许你自己租户内的用户授权。**企业微信扫码流程不是这样：**任何组织中任何有企业微信账号的人，只要在 MCP 客户端中打开你的 `<base>/mcp`，就能扫码并获得一个可用的 MCP 服务，费用记在你的 AWS 账号上。`wecom-cli` 不提供企业 ID（corp ID），所以服务无法按组织过滤。

开启 `wecom.requireApproval: true` 后：
1. 新用户扫码并在企业微信中完成授权，页面显示"授权成功，正在等待管理员审批"。
2. 运维人员执行 `npm run users -- list`，找到 `pending_approval` 的那一行，确认身份后执行 `npm run users -- approve <userId>`。
3. 用户在客户端中重新连接 MCP 服务器。

待审批用户永远拿不到 MCP access token。同一企业微信身份之后重新授权时，会保留已审批状态。

## 部署前（管理员）

1. 确认组织允许成员使用智能机器人 / AI 能力（CLI 与 MCP）。自 2026-08 起，企业微信已向所有规模的企业开放这些能力。如果你的组织限制了机器人，需要管理员在企业微信管理后台放开（以控制台为准，界面可能变化）。
2. 推广前，先把下文的 **7 天续期**和**绑定已有机器人**两条规则告知用户。
3. 决定是否开启 `wecom.requireApproval`（见上文）。

## 用户流程（部署后）

1. 用户在 MCP 客户端中添加 `<base>/mcp`（Stack 输出 `McpUrl`），客户端会打开浏览器。
2. 授权页显示二维码，用户用手机企业微信扫码，300 秒后过期。
3. 在企业微信中选择：
   - **第一次：**新建机器人。
   - **之后每一次：**选择**绑定已有机器人**。如果再次选"新建"，会**永久失去**对旧机器人所创建的文档、表格、日程的编辑权限。
4. 在企业微信中授予各项能力（文档、消息、日程、邮件等）。
5. 客户端加载出工具列表（开启审批时，要等管理员审批、用户重新连接之后）。

企业微信这边不需要登记回调 URL。

**Amazon Quick**（AWS Global）：按 [client-amazon-quick.md](client-amazon-quick.md) 操作，选择 **Default OAuth app**；第 4 步 Quick 打开的是企业微信扫码页，而不是 OAuth 授权页。

## 每 7 天续期一次能力授权（已接受的限制）

每项能力授权在授予后 **7 天**过期，之后调用会返回企业微信错误码 **850003**。没有接口可以自动续期，必须由用户**在企业微信客户端中手动续期**：

企业微信 → 智能机器人管理页 → 对应机器人 → 续期已过期的能力（以控制台为准，界面可能变化）。

服务的处理方式：
- 返回错误码为 `im_grant_expired`（`im_code: 850003`）的工具结果，其中 `user_action` 告诉智能体：授权在 7 天后已过期，请用户在企业微信智能机器人管理页续期，不要重新扫码，也不要新建机器人。
- 触发 CloudWatch 告警 `grant-expired`，发送到 Stack 的 SNS 主题；如果设置了 `alarm.webhookUrlSsmParam`，还会发到你的 webhook。
- 不会自动重新发起扫码授权，因为选"新建机器人"重新授权会丢失对象权限。

## 配置与密钥对照

| 值 | 位置 |
|---|---|
| `im: wecom` | `config/deploy.yaml` |
| 审批 / 扫码上限 | `wecom.requireApproval`、`wecom.maxPendingQr` |
| 应用凭证 | 无 |
| 每个用户的凭证 | 扫码流程生成，由服务存入 Secrets Manager `<slug>/users/<userId>`（每个用户一个密钥，专用 KMS 密钥） |
| 告警 webhook（建议配置，用于捕获 850003） | SSM 参数，参数名填在 `alarm.webhookUrlSsmParam` |

## 常见错误

| 错误码 / 现象 | 含义 | 处理 |
|---|---|---|
| `im_grant_expired`（**850003**） | 能力授权已过期（7 天） | 用户在企业微信智能机器人管理页续期 |
| 读取聊天记录时报 `im_policy_blocked`（**853006**） | 成员超过 10 人的企业不能读取群聊/单聊记录（平台策略） | 无法处理，较大的企业不可用 |
| 写文档/表格时报 `im_object_permission`（**851003**） | 机器人对该对象没有权限；机器人不继承用户已有的文档权限 | 让机器人创建文档后把用户设为管理员，或把文档共享给机器人 |
| `im_rate_limited`（**850005**） | 限流：每个机器人每分钟 50 次 | 稍后重试（服务已经自动退避重试两次） |
| `im_reauth_required`（893201） | 企业微信授权已失效 | 用户重新连接并扫码，选择**绑定已有机器人** |
| 二维码过期 / 超时 | 300 秒内没有扫码 | 刷新授权页 |
| 页面提示"正在等待管理员审批" | 开启了 `wecom.requireApproval`，且是新用户 | 运维人员执行 `npm run users -- approve <userId>`，用户重新连接 |
| 页面提示访问已被撤销 | 运维人员撤销了这个企业微信身份 | 对该身份的撤销是永久的 |
| HTTP 429"当前进行中的登录过多" | 达到 `wecom.maxPendingQr` 或单 IP 3 个的上限 | 稍等一分钟后重试 |
| 重新授权后失去旧文档的编辑权限 | 用户选择了"新建机器人" | 无法恢复，请始终选择"绑定已有机器人" |
| 调用报可信 IP 相关错误 | 组织启用了企业微信可信 IP | 尚未确认机器人通道是否受此限制，请反馈错误信息。v1 不提供固定出口 IP 方案 |

## 能力边界

- **每项能力每 7 天需要手动续期一次。**这是平台策略，本样例接受这一限制。
- **成员超过 10 人的企业无法读取聊天记录。**
- 消息只能发给用户本人，或机器人近期有过往来的会话，不支持群发。
- 依赖本地文件路径的工具（如媒体/微盘上传、页面导入）在远程模式下不可用，工具描述中会说明并给出内联替代方式。
- 每个机器人每分钟最多 50 次调用。
- 不开启 `wecom.requireApproval` 时没有租户边界（见上文和 [security.md](security.md)）。
